# ブラウザ拡張: 主要サイトでの動作確認（P4-05）

- 日付: 2026-11-16
- 方法: `apps/extension/e2e/sites.e2e.mjs --offscreen`。Playwright の Chromium 156 に拡張（開発版、ID 固定）を読み込み、実際の `zp-nmh` と金庫デーモン（サンドボックス内、ソフトウェアの鍵ストア）につなぐ。サイトごとにダミーのログイン（`zeropass.test@example.invalid` / `ZeroPass-dummy-1!`）をそのサイトの URL で金庫に入れ、ログイン画面を開き、利用者名の欄（なければパスワードの欄）を実際のクリックで選び、ZeroPass の候補から選んで、欄に値が入ったかを確かめる。**送信はしない**（実際のログインは行っていない）。
- ウィンドウを画面外に置いたブラウザで行った。ウィンドウなし（headless）では、Cloudflare などのボット対策の画面に止められるサイトが増える（同じ日の headless の結果: 26 サイト中 16）。

## 分かったこと

- 入力できなかった 6 サイトは、ボット対策・キャプチャ・読み込みの遅れで、ログインの欄までたどり着いていない。ログインの欄が出たサイトでは、すべて候補を出して入力できた。
- **ログイン画面が別のサイトにあるサービス**（Wikipedia → wikimedia.org、Notion → notion.com）では、サービスのトップの URL で保存したログインは出ない。eTLD+1 の厳密な照合（`extension.md` §5）の結果で、意図どおりである。保存の提案（P4-06）は、ログイン画面のオリジンで保存する。
- Apple のように同じサイトの iframe の中にあるログインの欄にも入力できる。別のサイトの iframe には入力しない（`apps/extension/e2e/local.e2e.mjs` で確認）。

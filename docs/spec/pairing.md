# ZeroPass ペアリング・チャネル仕様（pairing.md）

- 版: 0.1（ドラフト。G-01 でバージョン 1 として凍結する）
- 関連: [sync.md](sync.md)、[crypto.md](crypto.md)、[ADR-0005](../adr/0005-noise-patterns-and-sans-io.md)、[脅威モデル](../threat-model.md) §5.2
- 実装: `crates/zp-pairing`（入出力を持たない）

端末間の通信はすべて Noise Protocol で暗号化する。本書は、(1) 新しい端末を金庫に参加させるペアリングと、(2) ペア済み端末どうしの同期チャネルを定める。BLE や LAN などの運び方は扱わない（`ble.md`、トランスポート層）。

## 1. 端末の鍵

| 鍵 | 用途 | 保管 |
|---|---|---|
| 端末署名鍵（Ed25519） | op と端末レコードへの署名 | 金庫鍵でラップして金庫ファイルに保存（`sync.md` §2.3） |
| チャネル鍵（X25519、Noise の静的鍵） | 同期チャネルでの相手認証 | 金庫ファイルに保存（金庫鍵では包まない） |

チャネル鍵は、金庫がロックされたまま同期できるよう、金庫鍵では保護しない。PoC では金庫ファイルに平文で置き、Phase 3 で OS の保護領域へ移す。チャネル鍵を盗まれても、得られるのは暗号文と署名済みの op だけである。金庫鍵と端末署名鍵がなければ、内容を読むことも op を偽造することもできない。

## 2. Noise の使い方

| 用途 | パターン | prologue |
|---|---|---|
| ペアリング | `Noise_XXpsk3_25519_ChaChaPoly_SHA256` | `"zeropass/v1/pairing"` |
| 同期 | `Noise_IK_25519_ChaChaPoly_SHA256` | `"zeropass/v1/sync" ‖ 0x00 ‖ vault_id(16)` |

- **ペアリング（XXpsk3）**: 双方が相手のチャネル鍵を知らない状態から始める。QR コードで渡した 32 バイトの使い捨て秘密を PSK として混ぜるので、QR を見ていない第三者は中間に入れない。
- **同期（IK）**: 接続する側（イニシエータ）は相手のチャネル公開鍵を端末レジストリから知っている。イニシエータのチャネル公開鍵は相手の鍵で暗号化して送るので、通信を見ている第三者には、どの端末が接続したか分からない。応答側は、受け取ったチャネル公開鍵がレジストリにあり、失効していないことを確認する。なければセッションを破棄する。
- prologue に `vault_id` を入れるので、別の金庫の端末とは握手が成立しない。
- 握手メッセージにアプリケーションデータは載せない。

### 2.1 枠と再鍵

握手後のデータは次の枠で送る。

```
frame = 長さ(2) ‖ Noise トランスポートメッセージ（65535 バイト以下）
```

- 1 枠の平文は 65519 バイト以下。アプリケーションのメッセージ（`長さ(4) ‖ 本体`、`sync.md` §7）は、必要なら複数の枠に分けて送る。
- 各方向について、65536 枠を送るごとにその方向の鍵を Noise の `Rekey` で更新する。送信側と受信側は枠の数を同じように数える。
- 復号に失敗した枠を受け取ったら、セッションを破棄する。再送や読み飛ばしはしない。

## 3. ペアリング

### 3.1 役割

| 役割 | 説明 |
|---|---|
| 既存端末 | 金庫を持ち、全ドメインを解錠した状態の端末 |
| 新規端末 | これから金庫に参加する端末 |
| 表示側 | QR コードを画面に出す端末。Noise の応答側になる |
| 読取側 | QR コードをカメラで読む（または文字列を入力する）端末。Noise のイニシエータになる |

既存端末と新規端末のどちらが表示側になってもよい。QR コードの `role` で区別する。

### 3.2 QR コード

```
text    = "ZP1:" ‖ Base64URL（パディングなし）(payload)
payload = version(1) ‖ role(1) ‖ psk(32) ‖ noise_pk(32) ‖ expires_at(8) ‖ hint の数(1) ‖ hint…
```

| フィールド | 値 |
|---|---|
| `version` | `0x01` |
| `role` | `0x01` = 表示側が既存端末、`0x02` = 表示側が新規端末 |
| `psk` | このペアリング専用の乱数 32 バイト |
| `noise_pk` | 表示側のチャネル公開鍵。読取側は握手で得た相手の鍵と一致することを確認する |
| `expires_at` | 有効期限（UNIX 秒、ビッグエンディアン）。発行から 60 秒 |
| `hint` | 表示側への接続方法（下表）。最大 8 個 |

| `hint` の種類 | 形式 |
|---|---|
| IPv4 | `0x01 ‖ アドレス(4) ‖ ポート(2)` |
| IPv6 | `0x02 ‖ アドレス(16) ‖ ポート(2)` |
| BLE | `0x03`（接続先の見つけ方は `ble.md`） |

- QR コードは 1 回のペアリングにだけ使える。握手が 1 回成功するか、有効期限が切れるか、握手に 3 回失敗したら、表示側はその QR コードを無効にする。
- 読取側は、期限切れ、未知の `version`、形式の誤りを拒否する。

### 3.3 手順

握手の完了後、同じチャネル上で次のメッセージ（Protocol Buffers）を交換する。

```
新規端末                                  既存端末
   │── JoinRequest ──────────────────────────▶│  device_id、sign_pk、noise_pk、name
   │                                          │  （利用者に端末名を示して確認を求める）
   │◀──────────────────────────── JoinGrant ──│  vault_id、端末レジストリ、金庫鍵
   │  （金庫ファイルを作成）                    │
   │── JoinAck ──────────────────────────────▶│
   │◀═══════════ 同期セッション（sync.md §7）═══▶│
```

1. **JoinRequest**: 新規端末は自分の鍵を生成して送る。既存端末は、`noise_pk` が握手で認証した相手の鍵と一致することを確認する。
2. **確認**: 既存端末は、参加しようとしている端末の名前を利用者に示し、承認を得る。QR コードを盗み見た第三者が先に接続した場合に、ここで気づけるようにするためである。
3. **JoinGrant**: 既存端末は新規端末の端末レコードに署名してレジストリに加え、次を送る。
   - `vault_id`
   - 端末レコードと失効レコードの全件（新規端末のレコードを含む）
   - 各ドメインの金庫鍵の全世代（`domain`、`key_epoch`、鍵 32 バイト）
4. **金庫の作成**: 新規端末は、その端末用のマスターパスワードを利用者に決めてもらい、金庫ファイルを作る。`VK-P` はそのパスワードから導出した鍵で、`VK-T` / `VK-K` はその端末のハードウェア鍵ストアでラップする。ハードウェア鍵ストアのない端末は `VK-T` / `VK-K` を保存せず、その場で破棄する（TOTP とパスキーは暗号文のまま同期されるが、その端末では開けない）。
5. **JoinAck**: 新規端末が金庫ファイルを保存できたことを知らせる。
6. **初回同期**: 続けて同期セッションを実行し、新規端末が全データを受け取る。

条件と注意:

- 既存端末は、金庫に存在する全ドメインを解錠していなければ JoinGrant を送れない。したがってペアリングにはマスターパスワードと生体認証の両方が必要になる。
- 金庫鍵は Noise チャネルの中でだけ運ぶ。チャネルの外（ログ、QR コード、同期プロセス）には出さない。
- マスターパスワードは端末ごとに別でよい。共有されるのは金庫鍵であり、パスワードではない。
- 途中で失敗した場合、新規端末は作りかけの金庫ファイルを削除する。既存端末側に残った端末レコードは、利用者が失効させる。

## 4. 同期チャネルの確立

1. イニシエータは、発見した相手（トランスポート層が端末を特定する）のチャネル公開鍵をレジストリから引き、IK の握手を始める。
2. 応答側は、握手で得たイニシエータのチャネル公開鍵をレジストリで照合する。未知または失効済みなら破棄する。
3. 握手が完了したら、§2.1 の枠の上で `sync.md` §7 のセッションを実行する。
4. セッションの Hello に含まれる `device_id` が、チャネル鍵に対応する端末のものと一致しなければ破棄する。

## 5. 検証

- PSK が違う、チャネル鍵がレジストリにない・失効している、`vault_id` が違う場合に握手が失敗する。
- 改変・並べ替え・再送された枠でセッションが破棄される。
- 期限切れ・使用済みの QR コードが拒否される。
- メモリ上のチャネルで、新規端末が参加後に全ドメインを解錠できる。
- 既存端末でいずれかのドメインがロックされていると JoinGrant を送れない。

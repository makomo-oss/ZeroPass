# ZeroPass プロセス硬化（hardening.md）

- 版: 0.1（ドラフト）
- 関連: [ADR-0004](../adr/0004-process-architecture.md)、[ADR-0006](../adr/0006-windows-sandbox.md)、[脅威モデル](../threat-model.md) §6、[ipc.md](ipc.md) §9
- 実装: `crates/zp-sandbox`（`harden_process`）、`bins/zp-vaultd`

金庫デーモン `zp-vaultd` は、解錠中、金庫鍵と平文をメモリに持つ。サンドボックス（`ipc.md` §9）は「デーモンから外へ」を塞ぐ。この文書は「外からデーモンの中へ」を塞ぐ対策を定める。

## 1. 想定する相手

同じ利用者の権限で動く、別のプログラム（脅威モデルの T5）。管理者権限を持つ相手と、OS そのものを掌握した相手は対象外である（脅威モデル §3）。

## 2. チェックリスト

デーモンは起動して最初に、秘密をメモリに置く前に、次を自分自身に適用する。適用できなかった項目は警告としてログに出し、起動は続ける。

| # | 対策 | 防ぐこと | Windows | Linux | macOS |
|---|---|---|---|---|---|
| 1 | クラッシュダンプを出さない | 異常終了のとき、メモリの内容がダンプファイルや障害報告に残る | 済 | 済 | 済 |
| 2 | ほかのプログラムにメモリを読ませない | 同じ利用者の別のプログラムが、プロセスを開いてメモリを読む・書く | 済 | P6-10 | P6-09 |
| 3 | デバッガを接続させない | デバッガでの実行の乗っ取り、メモリの読み出し | 済（2 に含む） | P6-10 | P6-09 |
| 4 | DLL の検索パスを固定する | 実行ファイルの隣やカレントディレクトリに置かれた同名の DLL を読み込む | 済 | 対象外 | 対象外 |
| 5 | 外部のコードを読み込ませない | フック、拡張ポイント、ネットワーク上の DLL、実行時に生成したコード | 済 | P6-10 | P6-09 |
| 6 | 秘密をスワップに出さない | メモリの内容がページファイルに書かれる | 済（P1-02） | 済（P1-02） | 済（P1-02） |
| 7 | 秘密を使い終えたら消す | 解放したメモリに鍵が残る | 済（P1-02） | 済（P1-02） | 済（P1-02） |
| 8 | クリップボードを自動で消す | コピーしたパスワードが、ほかのプログラムやクリップボードの履歴に残る | 済（§4） | P6-10 | P6-09 |

### 2.1 Windows での実現

| # | 方法 |
|---|---|
| 1 | `SetErrorMode` で障害のダイアログを出さない。処理されなかった例外は、Windows エラー報告に渡さずにプロセスを終える（`SetUnhandledExceptionFilter`）。Rust のパニックは、内容をログに出して終了コード 101 で終わる（異常終了にしない） |
| 2・3 | プロセスのアクセス制御リストを置き換え、利用者に残す権利を「実行ファイル名の問い合わせ」「プロセス情報の問い合わせ」「終了の待機」「終了」だけにする（情報の問い合わせは、`taskkill` などがプロセスを終わらせる前に求めるため残す。メモリの内容は含まない）。メモリの読み書き、スレッドの作成、ハンドルの複製、デバッガの接続に必要な権利は、利用者から外れる |
| 4 | `SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)` と `SetDllDirectory("")` |
| 5 | プロセス緩和ポリシー: 拡張ポイントの無効化、リモートのイメージの禁止とシステムディレクトリの優先、動的コードの禁止 |

### 2.2 Linux での実現

| # | 方法 |
|---|---|
| 1 | `setrlimit(RLIMIT_CORE, 0)` |
| 2・3 | 未実装（P6-10）。`prctl(PR_SET_DUMPABLE, 0)` で防げるが、これを設定すると `/proc/<pid>/exe` も読めなくなり、IPC の両端が相手の実行ファイルを確かめる方法（`ipc.md` §3）が使えなくなる。Linux のサンドボックスと合わせて、確かめ方を決める |

## 3. 限界

- **2 と 3 は壁ではない。** Windows では、プロセスの所有者である利用者は、アクセス制御リストを書き戻せる。それを行うプログラムは防げない。管理者（デバッグ特権）も防げない。防げるのは、プロセスを普通に開いて読もうとするプログラムである。
- **起動した親プロセス**は、子プロセスのハンドルを持っている。デーモンを起動するのは ZeroPass のクライアントで、起動のあとハンドルを閉じる。
- 対策 5 の「動的コードの禁止」は、Windows Hello の呼び出しと両立するかを実機で確かめていない（ADR-0006 の未確認事項と合わせて確認する）。

## 4. クリップボード

パスワードをクリップボードへコピーするのは、利用者が操作している UI のプロセスである（サンドボックス内のデーモンは、クリップボードに触れない）。UI は次を守る。

1. コピーから一定時間（既定 30 秒）が過ぎたら、クリップボードを消す。ただし、その間に利用者が別のものをコピーしていたら消さない。
2. UI が先に終了しても、消去は行われる。
3. Windows では、クリップボードの履歴とクラウド同期に載せない指定を付けてコピーする。

この動作は、UI が共通に使う部品 `crates/zp-clipboard` にある（Windows。macOS は P6-09、Linux は P6-10）。

- コピーした直後のクリップボードの通し番号を控え、消すときにその番号が変わっていなければ消す。クリップボードの中身は読まない。
- `zp-cli get <ID> --copy`（ログインのパスワード、ノートの本文）と `zp-cli totp <ID> --copy` がこれを使う。コピーのあと、30 秒後に消すだけの小さなプロセスを残して終了する。

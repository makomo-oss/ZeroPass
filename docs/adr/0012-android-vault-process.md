# ADR-0012: Android では金庫を分離プロセスのメモリ上で開き、ファイルと鍵ストアはアプリのプロセスが受け持つ

- 状態: 採用
- 日付: 2026-11-23
- 関連: [ADR-0004](0004-process-architecture.md)（決定 5）、[ADR-0007](0007-domain-processes-and-key-agent.md)、`docs/spec/android.md`、`docs/spec/ipc.md` §14、タスク P6-01・P6-02・P6-04

## 背景

ADR-0004 は、モバイルでは OS の制約上アプリ 1 つの中で動かし、Android では金庫を `isolatedProcess` のサービスに分離すると決めた。PoC のアプリ（P2-16）は、金庫・同期・ネットワークのすべてをアプリのプロセスで動かしていた。

`isolatedProcess` のサービスは、Android がアプリとは別の使い捨ての UID で起動するプロセスで、次の性質を持つ。

- 権限を何も持たない。`INTERNET` がないので、OS がネットワークのソケットを作らせない。
- アプリのデータディレクトリのファイルを開けない（SELinux の `isolated_app`）。Binder で渡されたファイル記述子の読み書きはできる。
- アプリの Android Keystore の鍵を使えない（鍵は UID ごと）。
- アプリのほかのプロセスとは UID が違うので、アプリのプロセスからそのメモリを読めない。

一方、Android Keystore の鍵を「使うたびに利用者の認証（生体認証または端末の PIN）」で守るには、`BiometricPrompt` に暗号操作（`CryptoObject`）を渡し、認証の後に同じプロセスで操作を終える必要がある。`BiometricPrompt` は画面（Activity）を持つプロセス、つまりアプリのプロセスからしか出せない。

したがって、ADR-0004 の分離をそのまま実装すると、金庫のプロセスは金庫ファイルも鍵ストアも自分では使えない。

## 決定

### 1. 金庫は分離プロセスで、デスクトップの金庫デーモンと同じ処理で動かす

金庫は `android:isolatedProcess="true"` のサービス（プロセス名 `:vault`）で動かす。中身は、デスクトップの金庫デーモン（`zp-vaultd`）の要求の処理（`Service`）を、すべてのドメインを持つ 1 つのプロセス（全体プロセスと同じ範囲）として使う。モバイルではドメインごとのプロセスに分けない（ADR-0004 の決定 5 のとおり）。

### 2. プロセスの間は、Binder で渡したソケットの組の上の IPC

アプリのプロセスは、金庫のサービスに `bindService` し、Binder の呼び出し `connect(ParcelFileDescriptor)` でソケットの組（`socketpair`）の一方を渡す。その上で `docs/spec/ipc.md` の要求と応答を話す（フレーム・`Hello`・中継はデスクトップと同じ）。接続 1 本ごとに Binder の呼び出しが 1 回で、中継（§11.2）の 2 本目もこうして開く。サービスはアプリの外に公開しない（`exported="false"`）ので、接続できるのはアプリ自身だけである。

### 3. 金庫ファイルはアプリのプロセスが持ち、金庫のプロセスはメモリ上で開く

- 金庫のプロセスは、SQLite のデータベースをメモリ上に置く（イメージ）。ファイルを開かない。
- アプリのプロセスは、接続のはじめに「イメージの保管役」として中継（`ImageHostAttach`）を始め、保存してあるファイルの中身を送る。金庫のプロセスはそれを開き（`Vault::open_image`）、それまでほかの要求には答えない。
- 金庫のプロセスは、要求で金庫が変わったら、**その要求に答える前に**新しいイメージを保管役へ送る。アプリのプロセスは一時ファイルに書き、`fsync` してから元のファイルと置き換え、済んだことを返す。答えを受け取った変更は、どちらのプロセスが落ちても失われない。
- イメージは暗号文と、デスクトップの金庫ファイルに平文で置いているもの（ID、時刻、チャネル鍵など。`threat-model.md` §9）だけである。アプリのプロセスが扱うのは、デスクトップで同じ利用者のプログラムが読める金庫ファイルと同じものである。

### 4. ハードウェア鍵ストアは、アプリのプロセスが鍵エージェントとして使う

アプリのプロセスが鍵エージェント（`ipc.md` §13.2）になり、`KeyAgentAttach` で金庫のプロセスにつなぐ。署名の代わりに、Android Keystore の HMAC-SHA256 の鍵（使うたびに利用者の認証が要る。StrongBox があればその中）でチャレンジの HMAC を計算する。HMAC は決定的なので、デスクトップと同じ `SignatureKeyStore`（`crypto.md` §7）がそのまま使える。結果はデスクトップと同じく、金庫のプロセスが 1 回ごとに作った鍵に封をして返す。実装 ID は `0x04`。詳細は P6-02 で `crypto.md` §7.2 に定める。

### 5. 同期とペアリングのネットワークは、アプリのプロセスが受け持つ

アプリのプロセスが同期デーモンの役をする。LAN（Rust の `zp-transport`）と BLE（Kotlin のセントラル）で相手の端末とつながり、同期は同期の要求（`ipc.md` §10、`RemoteOpLog`）、ペアリングは中継（§11）で金庫のプロセスに頼む。アプリのプロセスには金庫鍵がない。

### 6. まとめ: どのプロセスが何を持つか

| | アプリのプロセス | 金庫のプロセス（`:vault`） |
|---|---|---|
| UID・権限 | アプリの UID。`INTERNET`、Bluetooth、カメラなど | 使い捨ての UID。権限なし |
| ネットワーク | LAN・BLE（同期・ペアリング） | OS が許さない |
| 金庫鍵（VK-P・VK-T・VK-K）・デバイス署名鍵 | 持たない | 持つ（解錠中だけ） |
| 金庫ファイル | 読み書きする（暗号文） | 開けない。メモリ上のイメージだけ |
| Android Keystore | HMAC の鍵を使う（毎回、利用者の認証） | 使えない |
| 平文 | 画面・自動入力・パスキーの応答に出すもの（デスクトップの UI と同じ範囲、`ipc.md` §6） | すべて（解錠したドメイン） |

## 検討した代替案

| 案 | 却下理由 |
|---|---|
| 金庫をアプリのプロセスで動かす（PoC の形） | ネットワークを扱うプロセスに金庫鍵が入る（ADR-0004 の分離がない） |
| `android:process` だけで分けた別のプロセスに、seccomp でソケットを禁じる | アプリと同じ UID なので、アプリの権限が残る。`INTERNET` を持つアプリとして、システムのサービス（`DownloadManager` など）に通信を頼めるため、ソケットを禁じてもネットワークに届く。アプリのファイルと Keystore も使える |
| 分離プロセスに金庫ファイルの記述子を渡して、SQLite で直接開く | 渡された記述子の読み書きはできるが、SQLite はジャーナルのファイルを同じディレクトリに作り、開き直す。記述子だけで動かすには VFS を自作する必要があり、`unsafe` の FFI が大きくなる |
| Keystore の AES-GCM の鍵で VK-T・VK-K を直接ラップする | 復号した VK がアプリのプロセスのメモリに出る。HMAC なら出るのは KEK の材料で、それも封をして金庫のプロセスに渡す（ただし、アプリのプロセスが乗っ取られていれば、その材料と金庫ファイルから VK を導ける。この点は同じ）。デスクトップの `SignatureKeyStore` と鍵エージェントの仕組み・試験を使い回せる |
| ドメインごとに分離プロセスを分ける（デスクトップの ADR-0007 と同じ） | 分離プロセスはどれもアプリの UID とは別で、互いのメモリも読めないので効果はあるが、Binder の接続・保存の受け渡しがドメインの数だけ増える。最初の版では 1 つにし、必要なら後で分ける |

## 結果

- 金庫鍵は、ネットワークを持たず、アプリからもメモリを読めないプロセスにだけある。アプリのプロセスが乗っ取られても、読めるのは、デスクトップの UI と同じく、乗っ取られている間に利用者が開いたもの（と、そのとき扱う HMAC の結果）である。
- 金庫が変わるたびに、金庫全体のイメージを書き直す。かかる時間は金庫の大きさに比例する（計測は `android.md`）。モバイルの金庫は小さく、変更は利用者の操作と同期のときだけなので、受け入れる。
- 金庫のプロセスは、金庫全体（暗号文）をメモリに持つ。
- アプリがサービスから離れる（`unbindService`）と、Android は分離プロセスを終わらせ、鍵はメモリから消える。施錠と同じ効果である。
- アプリのプロセスが止まると、金庫のプロセスも終わる。保存の途中で止まっても、置き換えの前のファイルが残る。
- Android Keystore を使う処理は、利用者の認証のため、アプリの画面（Activity）が前面にあるときにしか動かない。自動入力・パスキーの要求は、OS がアプリの画面を出す仕組み（認証の `IntentSender`・`PendingIntent`）の中で行う（P6-05）。

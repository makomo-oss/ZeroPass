# ADR-0002: 鍵階層とドメイン分離

- 状態: 採用
- 日付: 2026-11-11
- 関連: PLAN §2.1、脅威モデル §5.3・§5.5、タスク P1-01〜P1-09、P1-13、P2-09

## 背景

設計原則③は「パスワードと 2 段階認証（TOTP）の鍵とメモリを完全に分離し、パスワード側が突破されても TOTP は生体認証なしでは開かない」ことを求める。1 本のマスター鍵から全データを守る従来構成ではこれを満たせない。

## 決定

金庫を 3 つの**ドメイン**に分け、ドメインごとに独立した金庫鍵（VK）を持つ。

| ドメイン | 金庫鍵 | 保護するもの | ラップする鍵 |
|---|---|---|---|
| P（Password） | VK-P | ログイン情報、メモ | KEK-P = Argon2id(マスターパスワード, salt) |
| T（TOTP） | VK-T | TOTP シード | 生体認証必須のハードウェア鍵 |
| K（Key / Passkey） | VK-K | パスキー秘密鍵 | 生体認証必須のハードウェア鍵 |

```
マスターパスワード ─Argon2id→ KEK-P ─unwrap→ VK-P
HW鍵(生体認証必須) ───────────unwrap→ VK-T   ※マスターパスワードからは導出不能
HW鍵(生体認証必須) ───────────unwrap→ VK-K
アイテム: ランダム DEK を VK-* でラップ、AAD = item_id ‖ domain ‖ version
端末ごと: Ed25519 端末 ID 鍵 / X25519 Noise 静的鍵
```

1. **VK はすべて CSPRNG で生成する。** 互いに、またマスターパスワードから導出しない。
2. **アイテムごとにランダムな DEK を持つ（エンベロープ暗号）。** DEK は所属ドメインの VK でラップし、AAD に item_id・domain・version を束縛して入れ替え・巻き戻しを検出する。
3. **鍵の型にドメインを持たせる**（`SecretKey<Domain>`）。ドメインの取り違えをコンパイル時に防ぐ。
4. **解錠状態はドメインごとに独立させる。** P を解錠しても T / K はロックのまま。
5. **ハードウェア鍵**は `HardwareKeyStore` トレイトで抽象化する（Windows Hello + TPM、Secure Enclave、Android Keystore / StrongBox）。HW 鍵を使えない端末では T / K ドメインを無効にする。ソフトウェア実装はテスト専用とする。
6. **端末間の VK 配布はペアリング時だけ行う。** 送信側で生体認証 → Noise チャネルで送信 → 受信側が自端末の HW 鍵（P は KEK-P）で再ラップする。
7. **リカバリーキット**として、全 VK を復旧鍵でラップした暗号化エクスポートを紙で保管できるようにする（P1-14）。
8. **メモリ分離**は、PoC ではドメインごとの別アリーナ（ページロック）、Phase 3 でドメインごとの別プロセスにする（ADR-0004）。

## 検討した代替案

| 案 | 却下理由 |
|---|---|
| マスター鍵 1 本から HKDF で VK-P / VK-T / VK-K を導出 | マスターパスワードが漏れると TOTP も復号でき、原則③を満たさない |
| TOTP をマスターパスワード＋生体認証の両方でラップ | 生体認証が通る端末上ではマスターパスワード漏洩の価値が上がるだけで、得るものが少ない。HW 鍵単独の方が単純 |
| DB 全体を 1 本の鍵で暗号化 | ドメイン分離ができず、同期層が平文を扱うことになる |

## 結果

- マスターパスワードが漏れても TOTP シードとパスキーは守られる（脅威モデル G5）。
- 端末を追加するたびに既存端末での生体認証が必要になる。
- HW 鍵のない環境では T / K 機能が使えない。この扱いは脅威モデル §8 の未解決事項として G-01 で再確認する。
- 正確なエンベロープ形式、Argon2id パラメータ、HKDF ラベルは `docs/spec/crypto.md`（P1-01）で定める。

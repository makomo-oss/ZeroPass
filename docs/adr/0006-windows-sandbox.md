# ADR-0006: Windows では vaultd を AppContainer で動かす

- 状態: 採用
- 日付: 2026-11-14
- 関連: [ADR-0004](0004-process-architecture.md)、脅威モデル §8-1、タスク P3-03、`docs/spec/ipc.md` §9

## 背景

ADR-0004 は、金庫デーモン `zp-vaultd` がネットワークを使えないことを、ビルド（依存の検査）と OS（サンドボックス）の両方で強制すると決めた。Windows での OS 側の方式は未決で、候補は AppContainer、制限トークン、WFP（Windows フィルタリングプラットフォーム）のルールだった。P3-03 で実機（Windows 11）で確かめた。

## 決定

**`zp-vaultd` を、capability を 1 つも持たない AppContainer の中で起動する。** 実装は `crates/zp-sandbox`、起動するのはクライアント（`zp-cli`）である。

実機で確かめたこと（`crates/zp-sandbox/tests/sandbox.rs` が、同じ検査プログラムをサンドボックスの外と中で動かして比べる）:

| 項目 | 外 | 中 |
|---|---|---|
| TCP で外へ接続する（自分自身、LAN 上のアドレス） | できる | **できない** |
| UDP のデータグラムを送る | 届く | **届かない** |
| 待ち受けたソケットに接続してもらう | できる | **できない** |
| 許可していないファイルを開く、ディレクトリを一覧する | できる | **できない** |
| 許可したファイルを開く、許可したディレクトリにファイルを作る | できる | できる |
| ローカル IPC を待ち受け、接続元の実行ファイルを確かめる | できる | できる（下記の対応が必要） |

AppContainer の中で動かすために必要だった対応:

1. **パイプの名前空間。** AppContainer のプロセスは、自分のコンテナの名前空間にしか名前付きパイプを作れない。デーモンは `\\.\pipe\LOCAL\<名前>` に作り、クライアントは `\\.\pipe\Sessions\<セッション>\AppContainerNamedObjects\<コンテナの SID>\<名前>` で開く。
2. **接続元の確認。** AppContainer のプロセスは、コンテナの外のプロセスを開けない。そのままでは、デーモンがクライアントの実行ファイルを調べられない。クライアントは接続の前に、自分のプロセスに「このコンテナは実行ファイル名を問い合わせてよい」（`PROCESS_QUERY_LIMITED_INFORMATION`）というアクセス権を足す。足さないクライアントは拒否される。
3. **ファイル。** コンテナに、デーモンの実行ファイル（読み取りと実行）、金庫ファイル（変更）、金庫のあるディレクトリ（ファイルの追加と、これから作られるファイルの変更）へのアクセス権を与える。ディレクトリの一覧と、そこにすでにある他のファイルへのアクセス権は与えない。

## 検討した代替案

| 案 | 却下理由 |
|---|---|
| 制限トークン／ジョブオブジェクト | どちらもネットワークを止める機能を持たない |
| WFP のルールで `zp-vaultd.exe` の通信を遮断 | ルールの追加に管理者権限が要る。実行ファイルのパスに結び付くので、別の場所にコピーされた実行ファイルには効かない。ファイルへのアクセスは絞れない |
| 権限を持つ仲介プロセスがパイプを受け、AppContainer 内のデーモンへ中継 | 平文の要求と応答が、ネットワークを使える仲介プロセスを通る。金庫の外に平文を出さないという目的に反する |

## 結果

- デーモンが乗っ取られても、ネットワークへ出られず、金庫のあるディレクトリの外のファイルも読めない。
- 権限の付与はファイルの ACL に残る。金庫のあるディレクトリでは、付与の後に他のプログラムが作ったファイルも、コンテナから読み書きできるようになる。金庫は専用のディレクトリに置くのがよい（インストーラの既定の場所は P3-07 で決める）。
- **未確認: AppContainer の中から Windows Hello を使えるか。** 生体認証の操作が要るので自動テストにできない。使えない場合は、確認画面を出す部分だけをコンテナの外のプロセスに分ける（P3-04 のドメイン別ワーカーと合わせて設計する）。確認できるまでの逃げ道として、`zp-cli --no-sandbox` でサンドボックスなしの起動ができる。
- macOS（App Sandbox）と Linux（seccomp / Landlock）は、それぞれの移植のときに `zp-sandbox` に加える（P6-09、P6-10）。それまで、これらの OS ではデーモンは通常のプロセスとして動く。

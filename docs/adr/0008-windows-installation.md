# ADR-0008: Windows ではマシン全体に（Program Files へ）インストールし、ログオン時は Run キーから起動する

- 状態: 採用
- 日付: 2026-11-15
- 関連: [ADR-0004](0004-process-architecture.md)、[ADR-0006](0006-windows-sandbox.md)、[ADR-0007](0007-domain-processes-and-key-agent.md)、脅威モデル §4（B1）・§5.6、タスク P3-07、P3-01、P8-03、`docs/spec/ipc.md` §3・§8・§9

## 背景

P3-07 は、インストーラ、ログオン時の起動、コード署名の準備を求める。決めることは、インストール先（利用者ごとか、マシン全体か）、形式（MSIX、MSI、スクリプト）、ログオン時の起動の方法、金庫の既定の場所である。

前提が 2 つある。

1. 金庫デーモンは、接続してきたプロセスを**実行ファイルのパス**で見分ける（`ipc.md` §3.1）。デーモンと同じディレクトリの `zp-cli` は UI、`zp-keyagent` は鍵エージェントの役割を得る。実行ファイルの**署名**の検査は、P3-01 で P3-07 に送られていた。
2. Windows Hello の資格情報は、アプリの識別子ごと（AppContainer ごと）に分かれる（ADR-0006）。鍵エージェントは識別子を持たない普通のプロセスとして、利用者の資格情報を使う（ADR-0007）。

当初、ユーザーへの報告では「利用者ごとのインストール（管理者権限なし）」を案として示した。

## 決定

1. **マシン全体のインストール（`%ProgramFiles%\ZeroPass`）にする。管理者権限が 1 度要る。** 利用者ごとの案は取り下げる。
   - 利用者ごとのインストール先（`%LOCALAPPDATA%\Programs` など）は、その利用者が書き換えられる。同じ利用者の権限で動くマルウェア（脅威モデルの T5）が `zp-cli.exe` を置き換えれば UI として、`zp-keyagent.exe` を置き換えれば鍵エージェントとして金庫デーモンに受け入れられ、`zp-vaultd.exe` を置き換えればマスターパスワードを受け取れる。メモリの読み出しと違い、一度で済み、再起動を越えて残る。パスによる確認は、ディレクトリを管理者しか書き換えられないときにだけ意味を持つ。
   - 署名の検査が入れば（P8-03）、利用者ごとのインストールも選べるようになる。
2. **形式はパッケージ化しない（MSIX にしない）。** パッケージの識別子を持つと Hello の資格情報の範囲が変わり、ADR-0007 で確かめた前提（エージェントは利用者の資格情報を使う）が崩れる。配布物は zip で、中の PowerShell スクリプト `install.ps1` / `uninstall.ps1` が導入と削除を行う（`packaging/windows/`）。スクリプトは短く、何をするかを利用者が読める。MSI など一般的なインストーラへの移行は、署名付き配布と合わせて P8-03 で決める。
3. **ログオン時は、`HKLM\...\CurrentVersion\Run` から `zp-autostart.exe` を起動する。** すべての利用者のログオンで動き、その利用者に金庫があれば、`zp-cli daemon autostart` を通じて金庫デーモン（サンドボックス内）と同期デーモンを起動する。金庫がなければ何もしない。
   - `zp-autostart` はコンソールを持たない（GUI サブシステムの）小さなプログラムで、`zp-cli` をウィンドウなしで起動するだけである。`zp-cli` を直接起動すると、ログオンのたびにコンソールの窓が一瞬出る。
   - 金庫デーモンをサンドボックスの中で起動できるのはクライアントだけ（コンテナへのアクセス権の付与を含む。`ipc.md` §9.1）なので、`zp-cli` を通す。
   - **Windows サービスにはしない。** サービスはセッション 0 で動き、利用者のデスクトップに Windows Hello の確認画面を出せず、利用者ごとの名前付きパイプやコンテナとも合わない。デーモンは利用者ごと・金庫ごとに動く（`ipc.md` §8）。
   - タスクスケジューラのログオン時のタスクも検討したが、Run キーで足りる（利用者のセッションで、利用者の権限で動く）。
4. **金庫の既定の場所は `%LOCALAPPDATA%\ZeroPass\Vault\vault.zpvault`。** `--vault` も `ZEROPASS_VAULT` もなければ `zp-cli` はここを使い、ディレクトリを作る。金庫専用のディレクトリにするのは、デーモンのコンテナにディレクトリ全体へのファイル作成の権限を与えるためである（ADR-0006 の「結果」）。macOS は `~/Library/Application Support/ZeroPass/Vault`、それ以外は `$XDG_DATA_HOME/zeropass/Vault`（なければ `~/.local/share/zeropass/Vault`）。
5. **Program Files の実行ファイルには、コンテナへの権限を付与しない。** 一般の利用者は Program Files のファイルのアクセス権を変えられないが、Program Files はもともと「すべてのアプリケーション パッケージ」（`S-1-15-2-1`）に読み取りと実行を許している。クライアントは、実行ファイルへの付与が拒否されたら、そのまま起動に進む。
6. **Windows ファイアウォールに、同期デーモンの受信を許す規則を 1 つ加える。** `zp-syncd.exe` だけ、プライベートネットワークだけ、相手はローカルサブネットだけ（`lan.md` の「リンクの外へ出ない」に合わせる）。規則がないと、Windows は同期デーモンが初めて待ち受けたときに各利用者に許可を求め、一般の利用者はそれを許可できない。公共のネットワーク（駅や店の Wi-Fi）では受け付けない。
7. **スクリプトは、管理者権限がなければ自分で昇格を求める。** 「インストールされているアプリ」からのアンインストールは、昇格せずにスクリプトを起動するためである。マシン全体の PATH は、保存されている形（`%変数%` を展開しない、値の種類 `REG_EXPAND_SZ` のまま）で読み書きし、項目が増減するときだけ書く。
8. **コード署名の準備。** `scripts/package-windows.ps1` は、証明書の拇印（と時刻印のサービス）を渡されれば、実行ファイルとスクリプトに Authenticode の署名をする。`install.ps1` は署名を確かめ、すべて同じ証明書で有効に署名されていれば発行者を表示し、そうでなければ警告する（`-RequireSignature` で拒否）。証明書の入手と、実行ファイルの署名による接続元の検査は P8-03 で行う。

## 検討した代替案

| 案 | 却下理由 |
|---|---|
| 利用者ごとのインストール（管理者権限なし） | 上の 1。署名の検査なしでは、同じ利用者のマルウェアが ZeroPass の実行ファイルを置き換えられる |
| MSIX | 上の 2。Hello の資格情報の範囲が変わる。署名なしではインストールできない |
| Windows サービス | 上の 3。セッション 0 から Hello の確認画面を出せない |
| 同期デーモンが金庫デーモンを起動する | ネットワークを使うプロセスに、コンテナへの権限の付与と金庫デーモンの起動を任せることになる（`ipc.md` §12.1 は、同期デーモンは金庫デーモンを起動しないと定めている） |

## 結果

- **確かめたこと**: `bins/zp-cli/tests/installed.rs` が、Program Files と同じアクセス権（所有者でも変えられない）のディレクトリから、サンドボックス内のデーモンとワーカーが起動し、TOTP まで使えることを確かめる（CI でも動く）。CI の `install-windows` は、まっさらなランナーで、パッケージの作成、インストール、ログオン時の起動（金庫がないときは何もしない、あるときは両方のデーモン）、使用、上書きインストール、アンインストールを通す。
- 管理者権限が要る。共有の PC では、管理者が 1 度インストールすれば、各利用者が自分の金庫を作れる。
- アンインストールは、実行中の ZeroPass を終わらせ（金庫は施錠される）、プログラム・Run キー・PATH の項目・ファイアウォールの規則・「インストールされているアプリ」の登録を消す。PATH は、インストールの前とまったく同じに戻る（CI で確認）。**金庫は消さない**。各利用者の AppContainer のプロファイル（`ZeroPass.Vault`）も残る（中身は空で、害はない）。
- 署名のないパッケージでは、Windows の SmartScreen が警告する。署名付きの配布は P8-03。
- 更新は、新しいパッケージの `install.ps1` を実行し直す（実行中の ZeroPass は終わらせてから置き換える）。更新の配布方式は P8-03。

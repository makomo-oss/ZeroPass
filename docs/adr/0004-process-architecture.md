# ADR-0004: プロセス構成と権限分離

- 状態: 採用
- 日付: 2026-11-11
- 関連: PLAN §2.2、脅威モデル §4、タスク P0-05、P3-01〜P3-06

## 背景

アーキテクチャ概要は 4 層分離モデル（L1 Vault Core Daemon、L2 UI・ブラウザ拡張、L3 Agent Broker、L4 ローカル近接通信）を定め、L1 は「インターネット通信の機能そのものを持たない」ことを求めている。これをコード規約だけでなく、OS とビルドの仕組みで強制したい。

## 決定

層ごとに別の実行ファイルにし、OS のプロセス境界で権限を分ける。

| バイナリ | 層 | ネットワーク | 金庫鍵 | 役割 |
|---|---|---|---|---|
| `zp-vaultd` | L1 | **なし** | 保持（Phase 3 でドメイン別ワーカーへ分割） | 暗号化、保存、TOTP 生成、パスキー署名 |
| `zp-syncd` | L4 | LAN / BLE のみ | **持たない** | 端末探索、Noise セッション、暗号文 op の送受信 |
| `zp-broker` | L3 | なし（stdio） | 持たない | AI エージェント向け MCP サーバー |
| `zp-nmh` | L2 | なし（stdio） | 持たない | ブラウザ拡張と vaultd の橋渡し |
| `zp-cli` / デスクトップ / モバイル UI | L2 | なし | 持たない | 人が操作するインターフェース |

1. **ネットワーク不能を 3 段で強制する。**
   - ビルド: `zp-crypto` / `zp-vault` / `zp-vaultd` の依存ツリーにネットワーク系クレートが入ったら CI を失敗させる（P0-05）。
   - OS: Windows は AppContainer（ネットワーク capability なし）または制限トークン、macOS は App Sandbox（network entitlement なし）、Linux は seccomp / Landlock で、vaultd のソケット作成を禁止する（P3-03、P6-09、P6-10）。
   - 検証: サンドボックス下でソケット作成が失敗することをテストで確認する。
2. **IPC** は Windows の名前付きパイプ / Unix ドメインソケットとし、Protobuf でメッセージを定義する（`zp-ipc`）。vaultd は接続元プロセスを検証する（実行ファイルのパス・署名、同一ユーザー）。
3. **鍵は vaultd の外に出さない。** UI へは表示に必要な平文フィールドだけを返し、syncd へは暗号文 op だけを渡す。ペアリング時の VK 配布も、vaultd が Noise ペイロードを暗号化してから syncd に渡す。
4. **ドメイン別プロセス**（Phase 3）: TOTP とパスキーはそれぞれ専用ワーカープロセスで扱い、VK-T / VK-K はそのプロセスだけが保持する（P3-04）。
5. **モバイル**は OS の制約上、単一アプリ内で動かす。Android は金庫を `isolatedProcess` サービスに分離し、iOS はアプリと Credential Provider Extension が App Group 経由で金庫を共有する（P6-01）。
6. **unsafe コード**はワークスペース既定で禁止（`unsafe_code = "forbid"`）。OS API の呼び出しが必要なクレートだけ、理由を書いて個別に許可する。

## 検討した代替案

| 案 | 却下理由 |
|---|---|
| 単一プロセス（UI に金庫を内蔵） | ネットワークを使う同期・拡張連携と金庫が同じアドレス空間に入り、「金庫はネットに繋がらない」を OS レベルで保証できない |
| 同期を vaultd 内のスレッドで実装 | vaultd にソケット権限が必要になり、L1 の前提が崩れる |
| ブラウザ拡張が直接ローカル HTTP サーバーへ接続 | ループバックでも他プロセスや Web ページから到達されうる。Native Messaging は接続元がブラウザに限られる |

## 結果

- syncd・broker・nmh・UI のいずれが侵害されても、金庫鍵は直接漏れない。
- プロセス間通信とデーモン管理（起動、単一インスタンス、更新）の実装コストが増える。
- OS ごとのサンドボックス実装が必要で、Windows での実現方式は P3-03 で実証する（脅威モデル §8-1）。

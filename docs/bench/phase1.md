- 計測日: 2026-11-11
- 計測方法: `cargo bench -p zp-vault`（criterion、release 相当のプロファイル）
- ベンチマーク定義: [`crates/zp-vault/benches/vault.rs`](../../crates/zp-vault/benches/vault.rs)

| 項目 | 値 |
|---|---|

## 結果

値は criterion の推定値（中央の値）と 95% 信頼区間。

| 計測項目 | 結果 | 信頼区間 | 目標 | 判定 |
|---|---|---|---|---|
| マスターパスワードでの解錠（較正済み Argon2id） | 542 ms | 524〜563 ms | 1 秒未満 | 達成 |
| 1 万件の一覧（全件復号） | 61.8 ms | 60.4〜63.3 ms | 100 ms 未満 | 達成 |
| 1 万件から検索（1 件ヒット） | 62.8 ms | 61.6〜64.0 ms | - | - |
| 1 万件から検索（111 件ヒット） | 61.9 ms | 60.6〜63.4 ms | - | - |
| 1 件の取得（1 万件の金庫から） | 59.8 µs | 56.6〜63.4 µs | - | - |
| 1 件の追加（ディスク同期込み） | 2.80 ms | 2.72〜2.89 ms | - | - |
| 1000 件の一括追加（1 トランザクション） | 145 ms | 138〜152 ms | - | - |

補足:

- 解錠時の Argon2id パラメータはこのマシンで較正した値で、`m` = 64 MiB、`t` = 14、`p` = 1（目標 約 500 ms）。解錠時間のほぼすべてが鍵導出である。
- 1 万件のログイン情報を入れた金庫ファイルは 4.1 MiB（1 件あたり約 430 バイト）。
- 一覧は 1 件ごとに「アイテム鍵のアンラップ」と「本体の復号」の 2 回の AEAD 開封と Protocol Buffers の復号を行う。1 件あたり約 6 µs。
- 検索は全件を復号してからメモリ上で照合するため、所要時間は一覧とほぼ同じで、ヒット件数にはほとんど依存しない。平文の索引は持たない（`docs/spec/crypto.md` §9）。

## 所見と今後の課題

- Phase 1 の目標（解錠 1 秒未満、一覧 100 ms 未満）はどちらも満たした。
- 一覧・検索は件数に比例する。数万件規模やモバイル端末では 100 ms を超える見込みなので、Phase 4（UI）では解錠中の復号結果をメモリに保持する、表示分だけ復号するなどの対策を検討する。
- 1 件ずつの追加はディスク同期（`synchronous = FULL`）が支配的で約 3 ms。インポートや同期の取り込みでは一括書き込み（`insert_many`）を使う。
- モバイル端末（Android / iOS）での計測は Phase 6 で行う。Argon2id はメモリ 64 MiB を前提にしているため、低メモリ端末での較正結果を確認する必要がある。
